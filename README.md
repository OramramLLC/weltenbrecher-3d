# Weltenbrecher 3D

Concept models of Weltenbrecher's vehicles and weapons, built for look development: to settle silhouettes, scale and mechanical logic before anything is drawn, storyboarded or built as a miniature.

Every model is generated by code. Each batch has a Python generator driven by a parameter file. Change a number, re-run, and the model, the exports and the review sheets all rebuild. The `.blend` and `.glb` files are outputs, not sources.

## Pipeline

Every vehicle goes through three stages, and each stage ends at a review gate. Nate approves the gate before the next stage starts.

| Stage | What gets built | Gate question |
|---|---|---|
| 1. Blockout | Hull, turret, running gear, gun at correct overall dimensions | Does the silhouette read, and do the proportions match canon? |
| 2. Functional detail | Hatches with opening envelopes, vision devices, grilles, tow gear, weapons, crew access | Could a crew actually operate this thing? |
| 3. Finish | Surface treatment, weld and cast texture, markings, beauty renders | Is it ready to show someone? |

Beauty renders come from `beauty.py`, which renders the finished `.blend` with Blender's Cycles renderer. Cycles runs on the CPU in the cloud workspace, so preview renders are made there. Final high-sample renders can be made on Nate's own machine with the same script. The measured gray review sheets come from a separate OpenGL renderer that works from the exported `.glb` files, which doubles as an export check.

## Conventions

- **Units:** metres, with +X forward, +Y left and +Z up. The ground plane is Z = 0.
- **Every dimension lives in `params.json`.** Nothing is hard-coded in the generator.
- **Proposals are tagged.** Any value Claude chose that isn't fixed by canon or by Nate gets `"proposal": true` and is listed in that stage's notes file. Once Nate approves it, the tag comes off.
- **Notes record why.** Every change made after looking at a render goes in the notes with its reason. Example: "turret narrowed because it read as a fixed casemate."
- **Checks run on every build.** The stage report confirms overall envelope against target, track and wheel ground contact, hatch clearances, and that mirrored parts are real mirrored meshes. Negative scale breaks some glTF viewers.
- **Approved decisions are dated** in the notes under "Review decisions".

## Canon reference

Controlling canon is the *Weltenbrecher World and Story Bible v6.0*. Items marked **[open]** are deliberately undecided. Propose options for these and wait for a decision; don't settle them silently.

- **Kaisersturm**: German heavy tank. Ausf. B in 1943, upgraded to Ausf. D/E by the Livorno landings.
- **M12A2 Bastion**: American tank. The Bastion Calliope is a rocket-armed variant.
- **LK700 Mammut**: a 720-tonne rail-deployed land cruiser, and Germany's late-war, last-ditch gamble in the southern offensive. Tank size in this world is capped by the Continental Heavy Gauge, so the Mammut's transport and deployment by rail has to be believable. **[open]** Rail configuration, how it detrains, powerplant, armament.
- **Weltenbrecher**: a strategic railway supergun with a range of about 50–70 km, used to deliver the atomic shot. It is kept in a subterranean gallery and run out on its track only to fire. **[open]** Calibre, mounting, recoil system, gallery and firing-spur layout.
- **Production intent**: these designs may become miniatures and practical effects. Designs should be buildable as physical models, and the Stage 2 detail is what a model-maker would need.

## Getting started in a cloud session

1. Unpack the latest checkpoint zip into `batches/01_kaisersturm_bastion/`, with outputs into `out/` and sheets into `renders/`.
2. Install dependencies: `pip install bpy numpy scipy trimesh pyrender pillow` (bpy is headless Blender, including Cycles). `render.py` also needs the system EGL/Mesa libraries (`libegl1 libegl-mesa0 libgl1-mesa-dri`) and DejaVu fonts.
3. Run `generate.py`, then `render.py`, then `beauty.py`. Confirm the stage report passes before changing anything. From Stage 3 on, `generate.py` bakes the finish textures, which takes about 30–40 minutes on a 4-core cloud machine.
4. Commit generated outputs only at review gates, alongside the checkpoint zip.

## Git notes

- Ignore `__pycache__/`, `*.blend1` (Blender's autosave backups) and scratch files.
- `.blend`, `.glb` and `.png` are binary files. Blockout files are small enough to commit normally. If any single file approaches GitHub's 100 MB limit (the Mammut at Stage 3 might), switch those types to Git LFS.
